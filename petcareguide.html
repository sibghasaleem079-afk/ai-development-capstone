Pet Care Guide

A Java desktop application built during my second semester, to bring basic pet care information into one simple place.

Complete — within its original scope
Java OOP Swing AWT
01 · The Problem

I have a cat, and my friends have pets too. Whenever something came up — a health issue, a grooming question, or just wanting to keep a routine — I'd end up searching Google, asking GPT, or checking a few different websites to piece together an answer. The information was always scattered.

I also had no simple way to track how much I was spending on my pet each month.

I wanted one application that brought the basics together: routines, health tips, grooming guidance, and expense tracking, all in one place.

02 · What I Did

This was my final project for second semester, so I built it using the Java, OOP, and GUI knowledge I had at that point — Java Swing and AWT for the interface, and core OOP concepts (inheritance, encapsulation, polymorphism) to organize the code.

How it works

The user starts at a welcome screen, then selects their pet type — cat, dog, or bird. Based on that choice, they get access to four features:

  • Routine Guide — basic guidance for morning, evening, and night routines (feeding, playing, and other daily activities).
  • Healthy Tips — the user picks a common health problem (like fever) and gets information on it, including when to consider seeing a vet.
  • Grooming Information — covers activities like bathing, nail trimming, and brushing, with guidance on how often to do them.
  • Expense Tracker — lets the user log expenses month by month, January through December, and calculates the yearly total.

Some decisions I made along the way

  • I kept the scope to three pet types (cat, dog, bird) instead of trying to cover everything, since this needed to be realistic for where I was as a second-semester student.
  • I structured the app around a set of connected frames (PetCareFrame, WelcomeFrame, MainOptionFrame, ExpandFrame, RoutineFrame, and pet-type classes), so the user could move between the welcome screen, the main options, and each feature, and back again.
  • For the Expense Tracker, I used a HashMap<String, Double> with the month as the key and the expense amount as the value. Entering an amount calls expenses.put(month, amount) — so if you enter a new amount for a month you've already filled in, it replaces the old one rather than adding to it. To get the yearly total, showTotal() loops through expenses.values() and sums them up.
  • The Routine Guide, Healthy Tips, and Grooming Information content is static — written directly into the application rather than pulled from a database. That was a deliberate scope decision, not an oversight: I wanted to focus on getting the structure and flow of the app right first.

Along the way, I had to learn some GUI concepts I hadn't used before, like building dropdown-style selections and wiring buttons to the right screens and functionality.

03 · What Came of It

I ended up with a complete, working desktop application — not a prototype. The full flow works: pick a pet, move through the four features, and go back to the main menu. The code is on my GitHub.

For a second-semester project, I think it does what I set out to do: take a problem I actually had, and turn it into something usable that ties several small but genuinely helpful pieces of pet care information together in one app.

04 · How I Used AI

I used ChatGPT as a coding and testing assistant, not as a source of the idea or the product decisions.

The problem I was solving, the features I chose, the pet types I picked, and the overall layout and user flow — all of that came from me. Where AI came in was when I hit coding problems: debugging errors, understanding why something wasn't working, and getting help implementing GUI concepts I was still learning, like the dropdown selections.

Looking back, ChatGPT was a support tool for getting unstuck technically, while the direction of the project stayed mine.

05 · Current Functionality, Limitations & What's Next

Working now

  • The full user flow, from pet selection through all four features and back
  • Routine, health, and grooming guidance for cats, dogs, and birds
  • Expense tracking by month, with an automatically calculated yearly total

Current limitations

  • Routine, health, and grooming content is static and built into the app — no database, so nothing can be updated without changing the code
  • Only three pet types are supported, with no breed-specific information yet
  • The Expense Tracker only holds data in memory while the app is running (in a HashMap) — no file or database storage, so entered expenses are lost when the app closes
  • No user accounts and no online or web access — it's a Java Swing desktop app

What I'd want to add, roughly in this order

  1. More pet types and breed-specific information.
  2. More depth in the health, grooming, and routine content — more conditions, more detailed guidance.
  3. Persistent data storage, so expenses and other data aren't lost when the app closes.
  4. General UX improvements as I learn more.
  5. Eventually, rebuild it as a web application with a proper frontend, backend, and database.

Pet Care Guide is where I started applying this way of working: notice a real problem, decide what would actually help, and build it with the skills I have at the time rather than waiting until I know everything. My projects have gotten more advanced since, but this is where that approach started.
